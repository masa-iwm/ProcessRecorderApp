# ProcessRecorderApp

[English](README.md) | 日本語

**「録画ボタンを押す前」の映像も残せる、常駐型のイベント録画アプリ**です。
画面・カメラなどの映像を常時バックグラウンドでバッファリングしておき、録画を開始すると
その直前数秒〜数十秒分の映像も遡って含めた MP4 ファイルを保存できます。

タスクトレイに常駐して動作し、複数の録画（レコーダー）を同時に扱えます。GUI から手動で
操作するほか、コマンドラインから起動してバックグラウンドで動作中のアプリへ録画開始／終了を
指示したり、**別アプリの UI を監視させて、待っていた表示が現れた・変わった・消えたときに
録画を自動で開始／終了させる**こともできます。

## 主な機能

- **直前バッファからのイベント録画** — 各レコーダーは常時、直近数秒〜数十秒（既定10秒）分の
  映像をメモリ上にバッファリングし続けます。録画を開始すると、このバッファの内容から
  MP4 ファイルへの書き出しが始まるため、「録画ボタンを押す前」に起きた出来事も記録に残せます。
- **複数レコーダーの同時録画** — 画面・カメラなど、映像ソースの異なる複数のレコーダーを
  同時に設定・録画できます。
- **常時録画** — 各レコーダーは、イベント録画とは別に、独自のフレームレート・解像度・
  エンコード設定で回り続ける録画も持てます。一定時間ごとにファイルが切り替わります
  （事前バッファは効きません）。
- **映像ソース** — 画面キャプチャ、Webカメラ（Media Foundation経由）、テストパターンに対応。
- **ライブプレビュー** — 選択中のレコーダーの映像を、アプリ画面上でリアルタイムに確認できます。
- **タイムスタンプ焼き込み** — 録画映像に日時が焼き込まれます。
- **ファイル名テンプレート** — 保存ファイル名は `{Now:yyyyMMdd_HHmmss}_{Name}.mp4` のような
  テンプレートで指定でき、日時・レコーダー名・環境変数・ユーザー定義の変数を埋め込めます。
- **別アプリの UI 変化をトリガに（UIA トリガ）** — 別アプリの UI 要素の出現・削除・値の変化を
  UI Automation で監視し、条件成立で録画を自動的に開始・終了できます。
  **条件が成立している間だけ録画する**こともできます（成立で開始し、成立しなくなったら停止）。
  発火した値は常に変数へ反映されるので（`{トリガID}`）、そのままファイル名にも埋め込めます。
  トリガは Settings 画面から、画面上の要素を採取するピッカーで作成します
  （[UiaTrigger](https://github.com/masa-iwm/UiaTrigger) ライブラリを使用）。
- **エラー時の自動リカバリー** — 映像ソースでエラーが発生した場合、一定時間後に自動的に
  録画を再開します。

## 使い方

### 起動とタスクトレイ

exe を実行するとタスクトレイに常駐し、ウィンドウは表示されません。
アプリを操作するには、タスクトレイアイコンを右クリックして **表示**（英語表示では *Show*）を選びます。

- ウィンドウの **最小化**・**閉じるボタン(×)** は、いずれもアプリを終了せずタスクトレイへ格納します。
- アプリを終了するには、タスクトレイアイコンを右クリックして **終了**（英語表示では *Quit*）を選びます
  （閉じるボタンを **Ctrl キーを押しながら** クリックしても終了できます）。

### 画面構成

ウィンドウ上部のメニューから、以下の画面を切り替えられます。

| 画面 | 内容 |
|---|---|
| **Preview** | レコーダーごとのライブプレビューと設定（映像ソース・バッファ秒数・ファイル名テンプレートなど）。左側のプロパティ欄で編集し、右側に映像が表示されます。レコーダーの追加・削除もここから行います。 |
| **Log** | アプリ内部の動作ログをターミナル表示します。ANSI の色と `` による行上書きがそのまま出ます。保持する行数には上限があり、表示される前に破棄された行があればログ中に明示します。 |
| **Variables** | ファイル名テンプレートで使う変数（キーと値）を一覧・編集します。 |
| **Settings** | ウィンドウサイズなど、アプリ全体の設定です。UIA トリガの作成・編集（「…」ボタンからエディタとピッカーを開く）と、トリガごとの録画操作（なし／開始／終了／条件成立中のみ録画）・対象レコーダーの割り当てもここで行います。右上の**「再読み込み」**ボタンは、手で `settings.json` を書き換えたときに、その内容をディスクから読み直します（録画中・書き出し中は押せません）。 |

画面下部（メニューの足元）には、**全レコーダーを一括で開始／終了するボタン**もあります。
個別のレコーダーの開始／終了は、Preview 画面内の各レコーダーの操作から行います。

映像ソースの詳細設定（画面キャプチャの対象モニタ、カメラの解像度など）は、Preview 画面の
プロパティ欄から「パイプライン編集」ダイアログを開いて設定します。

プレビューには**構図の補助線**（三分割・黄金比・十字・正方形）を重ねられます。
Settings 画面の `FramingGrid` で選びます。線は映像が実際に出ている範囲に合わせて引かれます。

### 別アプリの UI 変化で自動録画する

監視したい画面が出た・変わった・消えたときに、録画を自動で開始／終了できます。

1. **Settings 画面**を開き、「トリガ一覧」の行の **「…」ボタン**を押します。
   トリガーの編集ウィンドウが開きます。
2. **「新しく録る…」**を押すと要素選択（ピッカー）が開きます。監視したい画面上の要素へ
   マウスを合わせ（「マウス自動選択」を ON にしておくと追従します）、
   **「この要素で確定」**を押します。
3. 下段の**「トリガー条件設定」**で、いつ発火させるかを決めます。
   - **発火契機**: `ElementAppeared`（現れたとき）/ `ElementRemoved`（消えたとき）/
     `PropertyChanged`（値が変わったとき）/ `WhileMatching`（条件が成立したとき）
   - **条件が成立している間だけ録画したい場合**は、発火契機を `WhileMatching` にしたうえで
     **「成立しなくなった時も通知」にチェック**を入れます（これが無いと**録画が止まりません**）。
   - 相手のアプリが変化を通知してくれない場合は、**「ポーリング間隔 (秒)」に `1`** などを
     入れておくと、その周期で読み直します。
4. **「トリガーを追加」**→ 編集ウィンドウで **OK** を押すと保存されます。
5. Settings 画面の**「トリガの割り当て」**に、いま作ったトリガーの行が自動で増えています。
   その行を開いて、
   - **操作**: 「（なし）」／「録画を開始」／「録画を停止」／「条件成立中のみ録画」
   - **対象レコーダー**: 空欄なら全レコーダー

   を選びます。「（なし）」でも、発火した値は変数には反映されます。
   なお「条件成立中のみ録画」は、手順 3 の**「成立しなくなった時も通知」が入っていないと
   止まりません**。入っていないトリガーでは、選択肢の文字がそのことを教えてくれます
   （「条件成立中のみ録画 (停止しません: …)」）。
6. 発火した値は変数 `{トリガーの Id}` として使えるので、ファイル名テンプレートに
   埋め込めます（例: `{Now:yyyyMMdd_HHmmss}_{MyTrigger}.mp4`）。

> **監視するアプリで実際に試してください。** この機能はアプリが UI Automation で
> 「変わった」と知らせてくれることが前提で、**画面上で値が変わって見えることと、
> 変わったと通知されることは別**です。通知しないアプリでは上記の「ポーリング間隔」を使います。
> 思ったとおりに動かないときは、`activity.log` の `trigger.` で始まる行を見てください
> （発火したか、録画を開始／停止したか、なぜ見送られたかが 1 行ずつ残ります）。

### 出力ファイル

- 録画した映像は **MP4 ファイル**として保存されます。保存先はレコーダーごとのファイル名
  テンプレートで決まり、相対パスを指定した場合は**保存先フォルダー**（設定の
  `OutputDirectory`。既定では実行ファイルのあるフォルダー）が基準になります。
  `OutputDirectory` 自体に相対パスを書いた場合も、同じく実行ファイルのあるフォルダーからの
  相対として扱います。テンプレートに絶対パスを書いた場合はこの設定は使われません。
- 古い録画を**自動削除**できます。`RecordingRetentionDays` に残す日数を指定し
  （既定の `0` は削除しない）、`RecordingCleanupIntervalHours` で実行間隔を指定します。
  起動直後にも1回実行します。保存先フォルダーのサブフォルダーも対象で、削除するのは
  `.mp4` だけです。削除の結果からになったサブフォルダーは併せて削除しますが、
  保存先フォルダーそのものは削除しません。
- アプリの設定は `%LOCALAPPDATA%\ProcessRecorderApp\settings.json` に保存されます。
  同じ場所に **JSON Schema** を `settings.schema.json` として書き出し、設定ファイル側の
  `$schema` がそれを指します。JSON Schema に対応したエディタ（VS Code 等）なら、
  手で編集するときに補完と検証が効きます。同じ内容をリポジトリにも
  [docs/settings.schema.json](docs/settings.schema.json) として登録しています。
- 動作ログは `%LOCALAPPDATA%\ProcessRecorderApp\activity.log` に記録されます。
  記録されるのは、アプリの起動と終了、使用する H.264 エンコーダーの選択結果、
  レコーダーの初期化の成否、**録画の開始と終了（実際に書き出したファイル名と録画時間）**、
  録画エラーと自動復帰の試行、実行されたコマンドラインと終了コードです。
  1MB を超えると `activity.log.1` へ退避します（1世代のみ保持）。

  ```
  2026-07-26 12:00:51.233 INFO recording.start recorder='R1' file='C:\rec\R1_120050511.mp4'
  2026-07-26 12:00:56.417 INFO recording.stop  recorder='R1' file='C:\rec\R1_120050511.mp4' elapsedMs=5172 result=ok
  ```

## コマンドラインからの自動操作

同じ exe を引数付きで起動すると、既に常駐しているアプリへその指示が転送されます
（新しいプロセスは常駐しません）。ランチャーは**指示の実行結果を待ち、そのコマンドの
終了コードを返してから**終了します ── 通常は一瞬ですが、常駐ワーカーの起動直後などは
**最大 60 秒**待つことがあります。バッチファイルや外部スクリプトから録画を制御し、
**終了コードで成否を判定する**用途を想定しています。

| コマンド | 内容 |
|---|---|
| `ProcessRecorderApp.exe activate` | ウィンドウを表示します。 |
| `ProcessRecorderApp.exe start-recording-all` | すべてのレコーダーの録画を開始します。 |
| `ProcessRecorderApp.exe stop-recording-all` | すべてのレコーダーの録画を終了します。 |
| `ProcessRecorderApp.exe start-recording <対象>` | 指定したレコーダーの録画を開始します。`<対象>` は数値ならインデックス（0始まり）、それ以外はレコーダー名です。 |
| `ProcessRecorderApp.exe stop-recording <対象>` | 指定したレコーダーの録画を終了します。 |
| `ProcessRecorderApp.exe status` | レコーダーごとの状態を1行ずつ、TAB 区切りの `名前`・`初期化済み`・`録画中`・`直近のファイル`・`直近の障害` で出力します。初期化されていない、または直近の障害が残っているレコーダーがある場合は、その理由を標準エラー出力に示して終了コード `15` を返します。 |
| `ProcessRecorderApp.exe --set キー=値` | ファイル名テンプレートで使う変数を設定します（繰り返し指定可）。この変数はアプリが起動している間だけ有効で、`--persist` で指定しない限り `settings.json` には**保存されません**。 |
| `ProcessRecorderApp.exe --get [キー]` | ファイル名テンプレートの変数を取得します（繰り返し指定可）。キー省略時は全件を表示します。未定義のキーを指定した場合は、そのキー名を標準エラー出力に示して終了コード `11` を返します。 |
| `ProcessRecorderApp.exe --persist キー` | 指定した変数を `settings.json` に保存し、再起動後も残すようにします（繰り返し指定可）。未定義のキーの扱いは `--get` と同じです。 |
| `ProcessRecorderApp.exe --no-persist キー` | 指定した変数を `settings.json` に保存しないようにします。変数自体はそのセッションの間は残ります。 |
| `ProcessRecorderApp.exe ping` | 動作確認用。ログに記録するだけで、画面表示や通知は行いません。 |
| `ProcessRecorderApp.exe --help` | コマンド一覧を表示します。 |

コマンドの実行結果は、呼び出したコマンドプロンプト等の**終了コード**（`%ERRORLEVEL%` /
`$LASTEXITCODE`）で判定できます。`0` は成功、`0` 以外は何らかの失敗を意味します
（詳細は [src/README.md](src/README.md) を参照してください）。

例（バッチファイルから、特定のレコーダーの録画を開始する）:

```bat
ProcessRecorderApp.exe start-recording "Recorder #1"
if errorlevel 1 echo 録画の開始に失敗しました
```

## 動作環境

- Windows 11（x64）
- インストール不要のアンパッケージ配布（Native AOT・自己完結ビルド）

## 入手方法

ビルド済みの配布物は
[Releases ページ](https://github.com/masa-iwm/ProcessRecorderApp/releases) にあります。
各リリースに zip が2種類あり、展開して `ProcessRecorderApp.exe` を実行するだけです
（何もインストールしません）。

- `ProcessRecorderApp-<バージョン>-win-x64-gstreamer.zip` — **同梱版**: アプリに必要な
  GStreamer ランタイムを同梱しています（LGPL 構成のみ。内訳は
  [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)）。これ単体で動きます。
- `ProcessRecorderApp-<バージョン>-win-x64.zip` — **非同梱版**: 第三者ランタイムを
  含みません。起動時に、利用者がインストールした GStreamer（MinGW 64-bit）を解決します。
  同梱版があえて外している `x264enc` など GPL のエンコーダーも含めて、自前の
  GStreamer を使いたい場合はこちらです。

- `src/ProcessRecorderApp/` — メインアプリケーション（画面・起動処理）
- `src/GStreamer.GirCore/` — 録画・プレビューエンジン
- `src/SingleInstance/` — 常駐化・多重起動制御
- `src/Components/` — 共通コンポーネント
- `src/Controls/` — GUIパーツ
- `docs/` — 開発ドキュメント（テスト基盤・CI・GPU 実機検証・ランタイム更新）

実装の詳細（アーキテクチャ・技術スタック）については [src/README.md](src/README.md) を
参照してください。
